Free Model Aggregator

One endpoint. The best free model, every request.

A routing server that aggregates a live catalog of free models behind a single OpenAI- and Anthropic-compatible endpoint — and answers every request with the best free model that can actually carry it.

What it does

Point any OpenAI or Anthropic client at this server and stop choosing models by hand. The server reads the catalog and quality ratings it is given, then, for every request:

Plans per request

Candidates are the best free models that meet the request's requirements — tools, vision, JSON mode, minimum context. Paid models are never candidates.

Translates across wires

Clients speak OpenAI or Anthropic; providers may also speak Gemini. Requests and answers are converted between wires without losing the system prompt, tools, images, output cap or stop sequences.

Fails over, rating first

When a provider refuses — a free tier spent, a rate limit, an outage — the request moves to the next candidate. A refusal only briefly dents a provider's standing, so one bad minute cannot bench the best model for the whole run.

Stays deterministic

Every routing choice derives from the catalog, the request and the providers' answers. No wall clock, no randomness: the same inputs always route the same way.

Endpoints

RouteWhat it serves
POST /v1/chat/completions OpenAI Chat Completions, as JSON or as a server-sent-event stream when stream is true.
POST /v1/messages Anthropic Messages, as JSON or as a server-sent-event stream when stream is true.
GET /v1/models The free model list, in the wire the auth header names: Authorization: Bearer gets the OpenAI shape, x-api-key gets the Anthropic shape.

Requests name the model "auto" — the choice is the server's. Send a request exactly as you would to the native API: system prompt, tools, images, max_tokens, stop sequences and JSON mode are all carried through to the provider that answers, and the answer comes back in your wire with the provider's own text, usage and stop reason.

The catalog

The catalog is one JSON document: every provider with its base URL, the environment variable that names its key, its wire, and each of its models with a free flag and a context length. It is built from the provider directory and the quality table alone, so the document the server registers and the one --list prints are the same document, byte for byte. 

{
  "providers": [
    {
      "id": "<provider>",
      "base_url": "<its base URL>",
      "key_env": "<its key variable>",
      "wire": "openai | anthropic | gemini",
      "models": [
        { "id": "<model>", "free": true, "context_length": 131072 }
      ]
    }
  ]
}

Running it

The entry is plain TypeScript on Node's standard library only — nothing to install.

node main.ts --list   # print the catalog document the server registers
node main.ts          # serve: register, answer requests, exit when done
  • --list prints the catalog — providers, models, endpoints and key variables — and exits 0.
  • With no catalog source available, --list prints {"providers":[]}.
  • In a trial the server registers its port and catalog, serves the workload, and exits 0 when the work is done.
